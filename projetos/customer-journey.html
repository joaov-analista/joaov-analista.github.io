Contexto do Projeto

Este projeto simula um cenário real de análise de experiência do usuário em um aplicativo bancário. O objetivo foi construir uma infraestrutura analítica completa — da geração dos dados até o dashboard executivo — capaz de responder perguntas críticas de produto: onde os clientes encontram mais dificuldades, quais perfis têm pior experiência e qual funcionalidade deve ser priorizada primeiro.

A base foi gerada inteiramente em Python com correlações de negócio realistas: personas com distribuições próprias de renda, segmento e comportamento, eventos com sazonalidade por hora e dia da semana, e erros com taxas diferenciadas por funcionalidade. Ao todo são 5 tabelas relacionais persistidas no PostgreSQL, com índices otimizados e 10 views analíticas prontas para consumo pelo Power BI.

O dashboard de 8 páginas responde perguntas estruturadas — cada página uma pergunta de negócio diferente — culminando em uma página de priorização que cruza clientes afetados, score de experiência e NPS para indicar onde agir primeiro.

import pandas as pd

# importar arquivos
clientes  = pd.read_csv("aplicativo bancario\\clientes.csv")
sessoes   = pd.read_csv("aplicativo bancario\\sessoes.csv")
eventos   = pd.read_csv("aplicativo bancario\\eventos.csv")
erros     = pd.read_csv("aplicativo bancario\\erros.csv")
avaliacoes = pd.read_csv("aplicativo bancario\\avaliacoes.csv")

def view(df, nome):
    print("="*90)
    print(f"{nome}")
    print(df.head(5).to_string())
    print(df.info())
    print("="*90)

# ===============================
# TRANSFORMAÇÃO GERAL
# ===============================

# tirar espaços de todas as bases e deixar tudo minusculo
def limpar_texto(df):
    for coluna in df.select_dtypes(include="object").columns:
        df[coluna] = df[coluna].str.strip().str.lower()
    return df

clientes   = limpar_texto(clientes)
sessoes    = limpar_texto(sessoes)
eventos    = limpar_texto(eventos)
erros      = limpar_texto(erros)
avaliacoes = limpar_texto(avaliacoes)

# ===============================
# TRANSFORMAÇÃO TABELA CLIENTES
# ===============================

# transformar faixa renda em categorico ordenado
ordem = ["até r$ 2.000", "r$ 2.001 – r$ 5.000",
         "r$ 5.001 – r$ 10.000", "r$ 10.001 – r$ 20.000",
         "acima de r$ 20.000"]
clientes["faixa_renda"] = pd.Categorical(
    clientes["faixa_renda"], categories=ordem, ordered=True
)
clientes["faixa_renda_cod"] = clientes["faixa_renda"].cat.codes  # 0 a 4

# verificar outliers em tempo_relacionamento e idade por IQR
for col in ["tempo_relacionamento", "idade"]:
    q1, q3 = clientes[col].quantile([0.25, 0.75])
    IQR    = q3 - q1
    out    = clientes[(clientes[col] < q1 - 1.5*IQR) |
                      (clientes[col] > q3 + 1.5*IQR)]
    print("="*90)
    print(f"OUTLIERS CLIENTES — {col}: {len(out)} encontrados")
    print("="*90)

# ===============================
# TRANSFORMAÇÃO TABELA SESSOES
# ===============================

sessoes["versao_app"]       = sessoes["versao_app"].astype("string")
sessoes["data_hora_inicio"] = pd.to_datetime(sessoes["data_hora_inicio"])
sessoes["data_hora_fim"]    = pd.to_datetime(sessoes["data_hora_fim"])

# extrair hora e dia da semana para análise de sazonalidade
sessoes["hora_inicio"] = sessoes["data_hora_inicio"].dt.hour
sessoes["dia_inicio"]  = sessoes["data_hora_inicio"].dt.day_name(locale="pt_BR")

# verificar outliers em duracao_segundos
q1_s = sessoes["duracao_segundos"].quantile(0.25)
q3_s = sessoes["duracao_segundos"].quantile(0.75)
IQR_s = q3_s - q1_s
outliers_s = sessoes[
    (sessoes["duracao_segundos"] < q1_s - 1.5*IQR_s) |
    (sessoes["duracao_segundos"] > q3_s + 1.5*IQR_s)
]
print("="*90)
print(f"OUTLIERS SESSOES — duracao_segundos: {len(outliers_s)} encontrados")
print("="*90)

# ===============================
# TRANSFORMAÇÃO TABELA EVENTOS
# ===============================

eventos["timestamp"] = pd.to_datetime(eventos["timestamp"])
eventos["hora_dia"]  = eventos["timestamp"].dt.hour
eventos["dia_semana"] = eventos["timestamp"].dt.day_name(locale="pt_BR")

# verificar outliers em tempo_segundos
q1_e = eventos["tempo_segundos"].quantile(0.25)
q3_e = eventos["tempo_segundos"].quantile(0.75)
IQR_e = q3_e - q1_e
outliers_e = eventos[
    (eventos["tempo_segundos"] < q1_e - 1.5*IQR_e) |
    (eventos["tempo_segundos"] > q3_e + 1.5*IQR_e)
]
print("="*90)
print(f"OUTLIERS EVENTOS — tempo_segundos: {len(outliers_e)} encontrados")
print("="*90)

# ===============================
# TRANSFORMAÇÃO TABELA ERROS
# ===============================

erros["tempo_resolucao"] = erros["tempo_resolucao"].astype("Int64")

# ===============================
# TRANSFORMAÇÃO TABELA AVALIACOES
# ===============================

avaliacoes["comentario"]      = avaliacoes["comentario"].replace("nan", None)
avaliacoes["data_avaliacao"]  = pd.to_datetime(avaliacoes["data_avaliacao"])

# exibir resumo final de cada tabela
for df, nome in [(clientes,  "CLIENTES"),
                 (sessoes,   "SESSOES"),
                 (eventos,   "EVENTOS"),
                 (erros,     "ERROS"),
                 (avaliacoes,"AVALIAÇÕES")]:
    view(df, nome)

# ===============================
# SALVAR BASES
# ===============================

bases = {
    "clientes":   clientes,
    "sessoes":    sessoes,
    "eventos":    eventos,
    "erros":      erros,
    "avaliacoes": avaliacoes,
}
for name, df in bases.items():
    df.to_csv(f"{name}_transformados.csv", index=False, encoding="utf-8-sig")
    print(f"{name} salvo")

-- CUSTOMER JOURNEY INTELLIGENCE — VIEWS ANALÍTICAS
-- ================

-- Onde os clientes encontram mais dificuldades?
CREATE VIEW vw_dificuldade_p_funcionalidade AS
SELECT
    funcionalidade,
    COUNT(*)                                  AS total_eventos,
    SUM(teve_erro::int)                       AS total_erros,
    ROUND(AVG(teve_erro::int) * 100, 2)       AS pct_taxa_erro,
    ROUND(AVG(tempo_segundos), 1)             AS media_tempo_segundos,
    COUNT(DISTINCT id_sessao)                 AS sessoes_afetadas
FROM eventos
GROUP BY funcionalidade
ORDER BY pct_taxa_erro DESC;

-- Quais funcionalidades geram maior frustração?
CREATE VIEW vw_frustacao_p_funcionalidade AS
SELECT
    e.funcionalidade,
    ROUND(AVG(s.score_experiencia), 1)        AS score_medio,
    ROUND(AVG(a.nps), 1)                      AS nps_medio,
    ROUND(AVG(a.csat), 1)                     AS csat_medio,
    COUNT(DISTINCT er.id_erro)                AS qtd_erro,
    SUM(CASE WHEN er.resolvido = false
        THEN 1 ELSE 0 END)                    AS erros_nao_resolvido
FROM eventos e
JOIN sessoes s  ON e.id_sessao  = s.id_sessao
LEFT JOIN erros er       ON er.id_evento = e.id_evento
LEFT JOIN avaliacoes a   ON a.id_sessao  = s.id_sessao
    AND a.aceitou_pesquisa = true
GROUP BY e.funcionalidade
ORDER BY score_medio ASC;

-- Em qual etapa ocorre o maior abandono?
CREATE VIEW vw_etapa_com_mais_abandono AS
SELECT
    e.funcionalidade,
    COUNT(*)                                   AS total_abandonos,
    ROUND(COUNT(*) * 100.0
          / SUM(COUNT(*)) OVER (), 2)          AS pct_do_total,
    ROUND(AVG(e.ordem), 1)                     AS ordem_media_abandono
FROM eventos e
JOIN sessoes s ON s.id_sessao = e.id_sessao
WHERE s.abandonada = true
  AND e.ordem = (
    SELECT MAX(e2.ordem)
    FROM eventos e2
    WHERE e2.id_sessao = e.id_sessao
  )
GROUP BY e.funcionalidade
ORDER BY total_abandonos DESC;

-- Qual funcionalidade gera maior impacto no NPS?
CREATE VIEW vw_nps_p_funcionalidade AS
SELECT
    e.funcionalidade,
    COUNT(DISTINCT s.id_sessao)                AS sessoes_com_funcionalidade,
    ROUND(AVG(CASE WHEN e.teve_erro = false
        THEN a.nps END), 2)                    AS nps_medio_sem_erro,
    ROUND(AVG(CASE WHEN e.teve_erro = true
        THEN a.nps END), 2)                    AS nps_com_erro,
    ROUND(
        AVG(CASE WHEN e.teve_erro = false THEN a.nps END) -
        AVG(CASE WHEN e.teve_erro = true  THEN a.nps END),
    2)                                         AS delta_nps,
    ROUND(
        (SUM(CASE WHEN a.nps <= 6 THEN 1 ELSE 0 END) -
         SUM(CASE WHEN a.nps >= 9 THEN 1 ELSE 0 END))
        * 100.0 / NULLIF(COUNT(a.id_avaliacao), 0),
    1)                                         AS nps_score
FROM eventos e
JOIN sessoes    s ON s.id_sessao  = e.id_sessao
JOIN avaliacoes a ON a.id_sessao  = s.id_sessao
    AND a.aceitou_pesquisa = true
GROUP BY e.funcionalidade
ORDER BY delta_nps DESC;

-- Quais padrões de erro afetam mais clientes?
CREATE VIEW vw_padroes AS
SELECT
    er.tipo_erro,
    e.funcionalidade,
    COUNT(DISTINCT er.id_erro)                 AS total_erros,
    COUNT(DISTINCT s.id_cliente)               AS clientes_afetados,
    COUNT(DISTINCT e.id_sessao)                AS sessoes_afetadas,
    ROUND(AVG(s.score_experiencia), 1)         AS score_medio_sessao,
    ROUND(AVG(er.resolvido::int) * 100, 1)     AS pct_resolucao,
    ROUND(AVG(er.tentativas), 1)               AS media_tentativas
FROM erros er
JOIN eventos e  ON e.id_evento = er.id_evento
JOIN sessoes s  ON s.id_sessao = er.id_sessao
LEFT JOIN avaliacoes a ON a.id_sessao = s.id_sessao
    AND a.aceitou_pesquisa = true
GROUP BY er.tipo_erro, e.funcionalidade
ORDER BY clientes_afetados DESC, score_medio_sessao ASC;

-- CUSTOMER JOURNEY INTELLIGENCE — VIEWS

-- 1. Onde os clientes encontram mais dificuldades?
CREATE VIEW vw_dificuldade_p_funcionalidade AS
SELECT
    funcionalidade,
    COUNT(*)                                        AS total_eventos,
    SUM(teve_erro::int)                             AS total_erros,
    ROUND(AVG(teve_erro::int) * 100, 2)             AS pct_taxa_erro,
    ROUND(AVG(tempo_segundos), 1)                   AS media_tempo_segundos,
    COUNT(DISTINCT id_sessao)                       AS sessoes_afetadas
FROM eventos
GROUP BY funcionalidade
ORDER BY pct_taxa_erro DESC;


-- 2. Qual funcionalidade gera maior impacto no NPS?
--    Delta NPS = diferença entre sessões com erro e sem erro
CREATE VIEW vw_nps_p_funcionalidade AS
SELECT
    e.funcionalidade,
    COUNT(DISTINCT s.id_sessao)                     AS sessoes_com_funcionalidade,
    ROUND(AVG(CASE WHEN e.teve_erro = false
              THEN a.nps END), 2)                   AS nps_medio_sem_erro,
    ROUND(AVG(CASE WHEN e.teve_erro = true
              THEN a.nps END), 2)                   AS nps_com_erro,
    ROUND(AVG(CASE WHEN e.teve_erro = false THEN a.nps END) -
          AVG(CASE WHEN e.teve_erro = true  THEN a.nps END), 2)
                                                    AS delta_nps,
    ROUND((SUM(CASE WHEN a.nps <= 6 THEN 1 ELSE 0 END) -
           SUM(CASE WHEN a.nps >= 9 THEN 1 ELSE 0 END))
           * 100.0 / NULLIF(COUNT(a.id_avaliacao), 0), 1)
                                                    AS nps_score
FROM eventos e
JOIN sessoes   s ON s.id_sessao = e.id_sessao
JOIN avaliacoes a ON a.id_sessao = s.id_sessao
    AND a.aceitou_pesquisa = true
GROUP BY e.funcionalidade
ORDER BY delta_nps DESC;


-- 3. Em qual etapa ocorre o maior abandono?
CREATE VIEW vw_etapa_com_mais_abandono AS
SELECT
    e.funcionalidade,
    COUNT(*)                                        AS total_abandonos,
    ROUND(COUNT(*) * 100.0
          / SUM(COUNT(*)) OVER (), 2)               AS pct_do_total,
    ROUND(AVG(e.ordem), 1)                          AS ordem_media_abandono
FROM eventos e
JOIN sessoes s ON s.id_sessao = e.id_sessao
WHERE s.abandonada = true
  AND e.ordem = (
      SELECT MAX(e2.ordem)
      FROM   eventos e2
      WHERE  e2.id_sessao = e.id_sessao
  )
GROUP BY e.funcionalidade
ORDER BY total_abandonos DESC;


-- 4. Padrões de erro: qual problema afeta mais clientes?
CREATE VIEW vw_padroes AS
SELECT
    er.tipo_erro,
    e.funcionalidade,
    COUNT(DISTINCT er.id_erro)                      AS total_erros,
    COUNT(DISTINCT s.id_cliente)                    AS clientes_afetados,
    COUNT(DISTINCT e.id_sessao)                     AS sessoes_afetadas,
    ROUND(AVG(s.score_experiencia), 1)              AS score_medio_sessao,
    ROUND(AVG(er.resolvido::int) * 100, 1)          AS pct_resolucao,
    ROUND(AVG(er.tentativas), 1)                    AS media_tentativas,
    ROUND((SUM(CASE WHEN a.nps <= 6 THEN 1 ELSE 0 END) -
           SUM(CASE WHEN a.nps >= 9 THEN 1 ELSE 0 END))
           * 100.0 / NULLIF(COUNT(a.id_avaliacao), 0), 1)
                                                    AS nps_score
FROM erros er
JOIN eventos   e ON e.id_evento  = er.id_evento
JOIN sessoes   s ON s.id_sessao  = er.id_sessao
LEFT JOIN avaliacoes a ON a.id_sessao = s.id_sessao
    AND a.aceitou_pesquisa = true
GROUP BY er.tipo_erro, e.funcionalidade
ORDER BY clientes_afetados DESC, score_medio_sessao ASC;

46% dos erros
LOGIN concentra quase metade de todos os erros
Com taxa de erro de 2,91% — quase o dobro do PIX (1,69%) —, o LOGIN afeta 5.254 clientes com score médio de 51,23. É a funcionalidade com maior volume absoluto de abandono: 79,53% das sessões abandonadas terminam aqui, antes do usuário sequer entrar no app.
65,14% vs 3,73%
Idosos abandonam 17× mais que o segmento Premium
A maior disparidade entre personas: idosos têm taxa de abandono de 65,14% contra 3,73% do Premium. Com 2.393 clientes (~12% da base), é o público com pior NPS médio (8,4) e menor CSAT (4,3) — indicando necessidade urgente de programa de acessibilidade digital.
2,2× mais tempo
Sessões com erro duram mais que o dobro
Sessões com erro duram em média 2,2× mais que sessões sem erro. O Chat tem o maior tempo mediano: 227 segundos. Isso indica que o usuário não abandona imediatamente — tenta resolver, gasta mais tempo e ainda assim encerra com score médio baixo.
Score 24 vs 94
Abandono vs logout normal: abismo de experiência
Sessões encerradas por abandono têm score médio de apenas 24, contra 94 das sessões com logout normal. Os termos mais frequentes nos comentários negativos são "lento", "travou" e "inaceitável" — concentrados nas funcionalidades LOGIN e PIX.
2,8× mais erros
Versão 5.8 do app multiplica os erros
A versão 5.8 gera 2,8× mais erros que a versão 6.1. A diferença de score entre versões é pequena (57 vs 60), mas o volume de erros criado pela versão antiga é suficiente para justificar uma atualização forçada como ação imediata de baixo custo e alto impacto.
4,5× menos erros
Conexão "boa" reduz erros 4,5× frente a "ruim"
Melhorar a qualidade de conexão de "ruim" para "boa" reduz a probabilidade de erro em 4,5×. A diferença de score entre conexão excelente (63) e ruim (53) é de apenas 10 pontos — indicando que parte do problema é de código do app, não só de infraestrutura.
